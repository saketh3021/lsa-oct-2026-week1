## The five traps, with evidence

### 1. `actual_duration_csv.xlsx` is an Excel file
The source file is a workbook (`actual_duration_csv.xlsx`), not text. Spark cannot read it, so extract converted it to `data/raw/actual_duration.csv` (137,793 rows). The untouched original is kept in `data/raw/original/`. Dates were written as `yyyy-mm-dd` in the conversion.

### 2. Byte-order mark in `national_categories.csv`
First header read as plain UTF-8: `'\ufeffappointment_date'`. BOM present: **True**. The other two files have clean first column names (`icb_ons_code`, `sub_icb_location_code`). Fix in transform: strip the BOM from the header (read with `utf-8-sig`, or `lstrip('\ufeff')`).

### 3. Dates are day-first text in `national_categories.csv`
- `appointment_date` loads as type `str` (text), e.g. `02/08/2021`.
- Rows whose first number is above 12 (impossible as a month): **497,166**. Rows whose second number is above 12: **0**. That proves the format is day/month/year.
- Parsing with `dd/MM/yyyy` gives a month equal to `appointment_month` on every row: **True**. This is the date test to reuse in Week 2.

### 4. Look-alike rows in `appointments_regional.csv`
- **21,604** rows are exact copies of an earlier row, carrying **274,766** appointments between them.
- They are real appointments, not errors: the sub-ICB columns were removed from this file, so two sub-ICBs in the same ICB can produce identical rows. **Sum them, never drop them.**
- Summing by every descriptive column gives **295,692** rows and the total stays **742,804,525** (unchanged: True).
- For comparison, dropping them would lose 274,766 appointments.

### 5. Untidy labels
- Booking-wait labels with double spaces: `15  to 21 Days`, `22  to 28 Days`, `8  to 14 Days`.
- Staff type values: `GP`, `Other Practice staff`, `Unknown`. The guide says the metadata spells it `Other Practice Staff` (capital S): standardise in transform.
- Alphabetical order of wait bands: `1 Day` < `15  to 21 Days` < `2 to 7 Days` < `22  to 28 Days` < `8  to 14 Days` < `More than 28 Days` < `Same Day` < `Unknown / Data Quality`. `1 Day` sorts before `Same Day`, so an explicit sort order is needed.
- Duration bands: `1-5 Minutes`, `11-15 Minutes`, `16-20 Minutes`, `21-30 Minutes`, `31-60 Minutes`, `6-10 Minutes`, `Unknown / Data Quality`.
- Service settings: `Extended Access Provision`, `General Practice`, `Other`, `Primary Care Network`, `Unmapped`.
- Context types: `Care Related Encounter`, `Inconsistent Mapping`, `Unmapped`.
- National categories: 18 distinct values.

## Other findings worth carrying forward

- Regional file: appointments with status `Unknown` are 4.6% of all appointments.
- Duration file: `Unknown / Data Quality` holds **40,284,086** appointments.
- Sub-ICB code is the text after the final ` - ` in `sub_icb_location_name` (`... ICB - 00L` gives `00L`). **Codes are not always 3 characters**: 9 of 106 locations have longer codes (e.g. `A3A8R`), so never take 'the last 3 characters'. Use a pattern such as `F.regexp_extract('sub_icb_location_name', r' - (\w+)$', 1)`.
- Check: with the pattern, every categories code appears in the duration file: **True**.
- Zero or negative counts: regional 0, categories 0, duration 0.
